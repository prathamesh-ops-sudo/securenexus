Close two verification gaps in Phase 07: add dispatcher-level permission checking to dispatchAction (RESP-01 requires dry-run to "check permissions") and add test coverage for permission enforcement (RESP-05 requires "permission checks" in test suite).

Purpose: The dispatcher currently relies solely on route-level isAuthenticated middleware. There is no check that the caller has the response_actions scope, that the orgId matches, or that high-risk actions require elevated roles. Without these checks, any authenticated user could dispatch actions across org boundaries.

       - `callerOrgId?: string` -- the org the caller actually belongs to (for cross-org check)

    2. Import ROLE_PERMISSIONS from "@shared/schema" at the top of action-dispatcher.ts.

    3. Create a `checkActionPermissions` function (not exported, internal to module):
       ```
       function checkActionPermissions(
         actionType: string,
         context: ActionContext,
       ): { allowed: boolean; reason?: string }
       ```
       Logic:
       a. If `context.callerOrgId` is provided AND `context.orgId` is provided AND they differ, return `{ allowed: false, reason: "Org boundary violation: caller org does not match target org" }`.
       b. If `context.callerRole` is provided:
          - Look up `ROLE_PERMISSIONS[context.callerRole]?.response_actions` -- if it does not include "write", return `{ allowed: false, reason: "Role ${role} lacks response_actions write permission" }`.
       c. Return `{ allowed: true }`.

    4. In `dispatchAction`, insert permission check between step 1 (Zod validation) and step 2 (dry-run check). After the validation passes (line ~130), add:
       ```typescript
       // Step 1.5: Check permissions (per RESP-01 gap closure)
       const permCheck = checkActionPermissions(actionType, context);
       if (!permCheck.allowed) {
         const denyResult: ActionResult = {
           actionType,
           status: "failed",
           message: `Permission denied: ${permCheck.reason}`,
           details: { permissionDenied: true, reason: permCheck.reason },
           executedAt,
         };
         await safeCreateAuditLog(context, actionType, config, denyResult, 0, false);
         return denyResult;
       }
       ```

    5. Update the safeCreateAuditLog call for permission denials to use action "response_action_permission_denied" instead of "response_action_executed". To do this cleanly, add a third possible action string by modifying safeCreateAuditLog to accept an optional `auditAction` parameter, defaulting to the existing isDryRun ternary. For the permission denial path, pass `"response_action_permission_denied"` as the auditAction.

    IMPORTANT: Do NOT change the function signature of dispatchAction (it remains `actionType, config, context`). The new fields on ActionContext are optional, so existing callers are unaffected. This is backward-compatible.
